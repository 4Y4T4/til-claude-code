# Today I Learned Claude Code
Claude Code学習記録

## 📋️Claude Codeの特徴
1. マルチファイル・マルチタスク対応
    - プロジェクト全体を理解し、複数のファイルを一気に編集可能
1. 並列実行能力
    - 複数のタスクを同時に処理し、開発速度が飛躍的に向上
1. 自然言語による対話的開発
    - 技術的な詳細を知らなくても、自然言語で指示するだけで実装が可能
1. 実行環境との深い統合
    - ターミナルでのコマンドの実行、テストの自動実行、デプロイまでを一貫してサポート
1. 環境に依存しない
    - プロンプトで軽快に動作するため、どのようなエディタや環境とも統合可能

## 🚀Claude Codeのセットアップ
1. Claude Codeのインストール
    ```sh
    # 最新版のインストールコマンド
    $ curl -fsSL https://claude.ai/install.sh | bash

    # 安定版のインストールコマンド
    $ curl -fsSL https://claude.ai/install.sh | bash -s stable
    ```
1. インストールの確認
    ```sh
    # バージョンが表示されればOK
    $ claude --version
    ```
1. 起動(コードエディタの拡張機能から起動でもOK)
    ```sh
    $ claude
    ```
1. CLAUDE.mdの作成
    ```sh
    $ /init
    ```

## ✒️コンテキストの管理
LLMは一見完璧に見えるが、計算量や特徴量の限界があるため、広大なコンテキストになればなるほど忘れやすく、間違いやすいという側面がある。
そこで、人間がコンテキストをマネジメントし、一貫性が保たれながら動作が保証されるようにルールや制限を整備していく必要がある。
Claudeではコンテキストウィンドウを最大20万トークン保持するように設計されている。
### コンテキストウィンドウ
1. コンテキストウィンドウの確認
    - 現在のコンテキストの占有状況を確認
        ```sh
        $ /context
        ```
1. コンテキストのリセット
    - 会話履歴をクリアしてセッションを新規で起動したような動作になる
        ```sh
        $ /clear
        ```
1. コンテキストの圧縮
    - 過去のやり取りを概要だけ残すことでコンテキストを圧縮する
        ```sh
        $ /compact
        ```
1. By the way(ところで)
    - 会話の履歴をコンテキストに残さずに質問する
        ```sh
        $ /btw 今回の変更について解説してください
        ```

## ⚙️Claude Codeの動作モード
Claude Codeには、ファイル編集やコマンド実行の際にどこまでユーザーの許可を求めるかを切り替える動作モードがある。
対話中に`Shift + Tab`を押すことでモードを切り替えられる。

| モード | 設定値 | 動作 | 主な用途 |
| --- | --- | --- | --- |
| デフォルト | `default` | ファイル編集やコマンド実行のたびに許可を求める | 慎重に進めたいとき |
| 編集自動承認 | `acceptEdits` | ファイル編集は自動で承認し、コマンド実行は許可を求める | 編集内容を信頼して作業を速めたいとき |
| プランモード | `plan` | ファイルの読み取り・調査のみを行い、編集や実行はせずに実装計画を提示する | 実装前に方針を検討・合意したいとき |
| オートモード | `auto` | 安全性を判定しながら、許可を求めずに自律的に作業を進める | 定型的な作業を任せたいとき |
| 権限確認スキップ | `bypassPermissions` | すべての許可確認をスキップする | サンドボックスなど隔離された環境でのみ使用 |

- 起動時にモードを指定することも可能
    ```sh
    $ claude --permission-mode plan
    ```

## 🛡️ガードレール
Claude Codeはセッションごとの状態を保持せず、LLMは過去のデータから統計的に答えを決めているので、時に暴れ馬のように前後の文脈をあまり理解せずにコードを書いてしまう事がある。
そのため、なるべく軸がぶれないように守るべき仕様や規約を事前にユーザーが固めておく必要がある。
### ガードレールの例
- コンパイルチェック
- 自動テスト
- Lintチェック
- DB/API/データスキーマの定義
